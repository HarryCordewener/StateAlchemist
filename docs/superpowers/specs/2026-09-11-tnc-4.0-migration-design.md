# TelnetNegotiationCore 4.0 — migration to StateAlchemist

**Status:** design, approved shape; not scheduled. **Depends on:** StateAlchemist published as a package.
**Spec it builds on:** [`2026-09-11-statealchemist-design.md`](2026-09-11-statealchemist-design.md).

TelnetNegotiationCore (TNC) drives its protocol handling with [Stateless](https://github.com/dotnet-state-machine/stateless):
one `StateMachine<State, Trigger>` per connection, configured at construction by every interpreter and plugin. This
document says what replacing it with StateAlchemist changes, what it cannot change, and in what order to do it.

## 1. Why

Measured on TNC's own shape, per byte fired: Stateless costs 246 ns and 1,344 B for a stay, 614 ns and 3,440 B for
a move across two levels; a kilobyte of ordinary text costs 259 µs and 1.4 MB. A generated StateAlchemist machine
costs 7.7 ns and nothing, 20 ns and nothing, and 21 ns and nothing — the last because text is a
[run](../../concepts/runs.md), captured in one call with a vectorised scan, which is the thing Stateless cannot
express at all. Constructing a machine costs 0.07 µs instead of the 4.4 ms and 2.2 MB TNC pays per connection.

That is the reason, but it is not the only gain. Today a mistake in a protocol's configuration — a trigger nothing
handles, two protocols claiming the same option byte, an `OnEntryFrom` whose parameter does not match the
parameterised trigger — is a runtime exception on a live connection, or silence. TNC has written its own analyzers
(`ConfigureStateMachineAnalyzer`, `PluginRequiredMethodAnalyzer` and friends) to catch some of that. With the
machine generated from declarations, those become the compiler's job: a conflict is `SALCH0101`, an uncovered leaf
is `SALCH0501`, a parameter that cannot bind is `SALCH0204`, and TNC's analyzers can be deleted.

## 2. What TNC has today

| Piece | Today |
|---|---|
| States | `enum State : short`, ~198 members, flat — hierarchy is convention (`State.SubNegotiation`, `State.DoNaws`, …) |
| Triggers | `enum Trigger : short` over byte values, plus `ByteOrTrigger` for parameterised triggers |
| Wiring | Each interpreter has a `Setup…(StateMachine<State, Trigger> tsm)` that calls `Configure`, `Permit`, `OnEntryFrom`, `PermitReentry` |
| Plugins | `ITelnetProtocolPlugin.ConfigureStateMachine(...)`, called during interpreter construction, at runtime |
| Per-connection data | Fields on the interpreter and on plugin instances, keyed by nothing: the machine has no data of its own |
| Text fast path | A hand-written bypass: ordinary text does not enter the machine at all (`perf(interpreter): stop firing the state machine for ordinary text`) |
| Observability | `OnTransitioned` logging at trace level |

## 3. The target shape

### States own their data

A flat enum of 198 members becomes a tree of structs, each holding what it is in the middle of:

```csharp
public struct Connected : IRootState { public int Width; public int Height; }
[Initial] public struct Accepting : IState<Connected> { }
public struct SubNegotiation : IState<Connected> { public byte Option; }
public struct Naws : IState<SubNegotiation> { public byte[]? Bytes; public int Index; }
```

The buffers, half-read window sizes and pending option bytes that live on interpreter fields today move into the
state that owns them, and are cleared when that state is left — which is the bug class TNC has fixed by hand more
than once.

### A protocol is a module, not a configuration call

Each `Setup…` and each plugin's `ConfigureStateMachine` becomes a `[Module]` of `[Transition]` declarations. The
application — TNC's own `MudTelnet`, or a host's — lists the modules it wants:

```csharp
[Machine(Root = typeof(Connected), Value = typeof(byte), Context = typeof(TelnetContext), Concurrency = Concurrency.Serialized)]
[Include(typeof(TelnetCore)), Include(typeof(NawsModule)), Include(typeof(GmcpModule))]
public sealed partial class MudTelnet;
```

**This is the breaking change that makes it 4.0.** Modules are chosen when the application compiles, so a plugin
cannot be discovered and attached at runtime. What TNC's plugin system gives — dependency order, per-protocol
enable/negotiated state, a context to talk back through — survives: order becomes transition `Order`, negotiated
state becomes state data or context fields, and the context is the machine's `Context`. What does not survive is
`AddPlugin(someTypeLoadedFromDisk)`.

### Triggers, runs and events

Byte triggers become `[On(value)]`, `[OnRange(low, high)]` and `[OnAny]`; `ByteOrTrigger`'s parameterised triggers
become ordinary parameters, bound by the generator. The text fast path becomes a `[Run]` transition — the same idea
TNC wrote by hand, now with the stop set computed from the machine's own transitions, so it cannot drift from what
the other transitions claim. Out-of-band triggers that are not bytes — a disconnect, a timeout, a keep-alive tick —
become `IEvent` types, which is what lets them reach a machine that is waiting on a decision.

### Where a decision is the right answer

Anything that asks the host a question mid-negotiation — authentication, a charset the host must approve, an MSSP
value fetched from elsewhere — becomes a `[Decision]`. The read loop stops reading while the decision is pending,
which is the backpressure TNC currently has to arrange by hand, and a disconnect event can cancel it.

### Concurrency

TNC reads from a `PipeReader` on one task and writes from another; protocol code also fires events. `Serialized` is
the mode that matches: any thread may fire, calls queue, one transition at a time, and the read loop's `FireAsync`
completes when its bytes have been processed. The inbox costs about 65 ns a call, paid once per buffer rather than
per byte.

## 4. Concept mapping

| Stateless | StateAlchemist |
|---|---|
| `Configure(state).Permit(trigger, target)` | `[Transition(From = typeof(S), To = typeof(T)), On(trigger)]` |
| `PermitReentry(trigger)` | a stay: `[Transition(From = typeof(S)), On(trigger)]` |
| `InternalTransition(trigger, action)` | a stay whose `Transform` does the work |
| `OnEntry` / `OnExit` | `[Entered(typeof(S))]` / `[Exited(typeof(S))]` |
| `OnEntryFrom(parameterised, (byte b) => …)` | the transition's own `Transform(byte value, …)` |
| `SubstateOf(parent)` | `IState<Parent>` |
| `InitialTransition` | `[Initial]` |
| guard clauses on `Permit` | `Guard`, with `Order` when several can match |
| `Fire(trigger)` | `FireAsync(value)`, or `Fire(value)` when nothing is async |
| `OnTransitioned(...)` | `partial void OnTransitioned(in TransitionInfo<byte>)` |
| `PermitDynamic` | a [decision](../../concepts/decisions.md), or a guard per outcome |
| UML export | the generated `Mermaid` and `Dot` constants |

## 5. Order of work

Each stage keeps TNC's tests green and is shippable on its own.

1. **The core, alongside.** Declare `Connected`/`Accepting`/`ReadingCharacters`/`SubNegotiation` and a
   `TelnetCore` module covering IAC, WILL/WONT/DO/DONT and subnegotiation framing. Put the generated machine behind
   the existing `IByteStreamTransform` seam, switched by a flag, and run TNC's whole unit suite against both.
2. **Protocol by protocol.** NAWS, GMCP, MSSP, MSDP, terminal type, EOR, prompt, keep-alive, charset, MCP — one
   module each, one commit each, tests green at every step. The interpreter keeps its public surface; only its
   insides change.
3. **The plugin surface.** Replace `ConfigureStateMachine` with "a plugin declares a module type", and make the
   builder validate at compile time what it validated at runtime. This is where the 4.0 break lands, and it wants
   its own design document.
4. **Delete.** The `Stateless` dependency, `Models/State.cs`, `Models/Trigger.cs`, `ByteOrTrigger`, the hand-written
   text fast path, and the analyzers that policed the old configuration.
5. **Measure.** Re-run TNC's own benchmarks on a real transcript, and publish the before and after.

## 6. What this does not change

TNC's wire behaviour, its public interpreter API (beyond the plugin registration point), its logging contract, or
its option negotiation semantics. The migration is a rewrite of how the machine is described, not of what it does:
every existing TNC test is a test of the new machine.

## 7. Risks

| Risk | Mitigation |
|---|---|
| The plugin model's break loses third-party protocols | Stage 3 gets its own design; a compatibility shim that runs an old plugin's configuration against a small interpreted machine is possible but should be measured before it is promised |
| 198 states become an unwieldy tree | The tree is what the states already mean; the generator reports an unreachable or uncovered one (`SALCH0501`, `SALCH0502`) rather than leaving it to a live connection |
| Negotiation order changes subtly | Transition `Order` is explicit where Stateless's was incidental; the tests that cover order are the gate |
| StateAlchemist is young | TNC is its first consumer and its reason to exist; anything TNC needs and cannot express is a StateAlchemist bug, fixed there — the contract suite makes that safe |

## 8. Open questions

- Does the machine live in TNC (one `MudTelnet` for everyone) or in the host application, which then chooses its
  own modules? The second is what StateAlchemist's whole-program generation is for, and it is the honest answer for
  a library whose users add protocols — but it moves a code-generation step into every host's build.
- How much of `ProtocolContext` survives as the machine's `Context`, and how much becomes state data?
- Does TNC keep an interpreted fallback for hosts that cannot run a source generator? Probably not: the generator
  needs only Roslyn 4.8, which the .NET 8 SDK ships.
